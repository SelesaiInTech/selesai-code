# Plan 2 — `/handoff-new` command

Focus: user-facing command that generates handoff content and opens a clean new session with that content as editable first prompt.

## Goal

Add a command such as `/handoff-new` (and optional alias `/handover-new`) that:

1. Summarizes current branch into a handoff prompt.
2. Starts a new session with parent tracking.
3. Puts the handoff content into the editor or optionally submits it.
4. Does not inject hidden system prompt context.

## Non-goals

- Do not change the skill loader.
- Do not auto-run implementation unless explicitly designed later.
- Do not persist handoff in repo by default.
- Do not use subagent runtime for this first version.

### Identification

Before modifying package registration, inspect `src/extensions/package.json` and root `package.json` to confirm how bundled extensions are declared.

### Change

Register commands:

```ts

```

Behavior:

- Require interactive/TUI mode for first version, because editor/new-session UX is TUI-owned.
- If no model selected: notify error.
- If no args: use default goal: `Continue the previous session from this handoff.`
- Gather branch messages using same compaction-aware logic from example.
- Generate handoff prompt with model completion.
- Redact instruction lives in system prompt.
- Open editor for user review.
- Call:

    replacementCtx.ui.setEditorText(editedPrompt);

Do not call `replacementCtx.sendUserMessage` in first version. User asked for initial prompt, not hidden system prompt; editor draft is safer and reviewable.

Optional later flag, not first version:

```txt

```

# Plan 3 — Engine-owned workflow loop

Focus: replace prompt-only implement/review loop with workflow-owned subagent orchestration.

## Goal

Make the workflow engine own this loop:

```txt
builder → commentator → builder → commentator → clean → loop-complete.md
```

The parent model should not be responsible for remembering the loop.

## Non-goals

- Do not rewrite pi-subagents.
- Do not introduce a database.
- Do not make a generic workflow framework.
- Do not enforce every possible phase semantically in this first pass.

## Task 3.1 — Discover adapter extension points

### Discovery

Inspect:

- `src/extensions/workflow/adapter.ts`
- `src/extensions/workflow/state-machine.ts`
- `src/extensions/workflow/modes/prototype.ts`
- `src/extensions/workflow/modes/quick.ts`
- `src/extensions/pi-subagents/src/extension/index.ts`
- `src/extensions/pi-subagents/src/extension/schemas.ts`
- `src/__tests__/adapter.test.ts`
- `src/__tests__/workflow-race.test.ts`

Find how an extension can call a tool internally. If the extension API cannot call registered tools directly, use `pi.sendUserMessage(...)` follow-up as the thin bridge for first version, but prefer direct API only if it already exists.

### Identification

Likely files to modify:

- `src/extensions/workflow/adapter.ts` — owns workflow-to-tool/event glue.
- `src/extensions/workflow/state-machine.ts` — only if new loop state needs pure representation.
- `src/extensions/workflow/modes/prototype.ts` and `quick.ts` — simplify loop prompts.
- Tests under `src/__tests__/adapter.test.ts` or new focused test.

Do not modify subagent runtime unless an existing API bug blocks this.

### Change

Implement minimum loop tracking in workflow adapter.

Add a small loop artifact contract. Prefer file if easier to inspect/debug:

```json
{
  "iteration": 1,
  "status": "reviewing" | "fixing" | "clean" | "blocked",
  "lastReviewPath": "...",
  "maxIterations": 3
}
```

Workflow behavior in `loop` phase:

1. Dispatch builder with explicit inputs: `plan.md`, `handoff.md`, `reuse.md`, and `research.md` if present.
2. Dispatch commentator after builder returns.
3. Force commentator output to `${artifactDir}/loop-review-1.md`.
4. Require commentator prompt to end with one machine-readable line:

```txt
WORKFLOW_REVIEW_STATUS: clean
```

or

```txt
WORKFLOW_REVIEW_STATUS: blocking
```

5. If blocking, dispatch builder with review file path, repeat.
6. If clean, write `loop-complete.md` and advance.
7. If max iterations reached, stop and ask user/supervisor rather than silently passing.

Ponytail simplification: marker parsing is enough for first version. Do not add JSON schema unless needed.

### Verification

Success cases:

- One clean review writes `loop-complete.md`.
- Blocking review triggers another builder call.
- Max iterations stops with clear user message and does not write `loop-complete.md`.

Failure cases:

- Missing plan/handoff path blocks with useful message.
- Commentator returns no marker: treat as blocked/needs attention, not clean.

Regression checks:

- Earlier phases still advance by artifact existence.
- Audit still works as before until Plan 4 is implemented.
- Existing `write_workflow_artifact` behavior unchanged.

Tests:

- Simulate builder subagent result then commentator clean result; assert `loop-complete.md` written.
- Simulate commentator blocking result; assert another builder prompt/tool path is queued or requested.
- Simulate max iterations; assert no close/advance.

### Change

Extend `WorkflowConfig` minimally:

```ts
artifactValidators?: Partial<Record<Phase, WorkflowArtifactValidator>>;
closeValidators?: Record<string, WorkflowArtifactValidator>;
```

Where validator is simple:

```ts
type WorkflowArtifactValidator = (content: string) => { ok: true } | { ok: false; reason: string };
```

Adapter owns file reading; state machine receives predicate result through deps to stay pure.

Suggested initial validators:

- `plan.md` must contain `WORKFLOW_PLAN_STATUS: ready`
- `handoff.md` must contain `WORKFLOW_HANDOFF_STATUS: ready`
- `loop-complete.md` must contain `WORKFLOW_LOOP_STATUS: clean`
- `review.md` must contain `WORKFLOW_REVIEW_STATUS: clean`

Update prompts to require these final lines.

When invalid:

- Do not advance.
- Return blocked reason like: `review.md exists but missing WORKFLOW_REVIEW_STATUS: clean`.

### Verification

Success cases:

- Valid marker advances.
- Missing marker does not advance.
- `review.md` with `blocking` does not close workflow.

Failure cases:

- Empty file does not advance for critical phases.
- Malformed marker gives clear message.

Regression checks:

- `requirements.md`, `research.md`, `reuse.md` can remain file-existence-only unless user wants stricter gates.
- Existing skip rule for reuse still works.

Tests:

- State-machine test for invalid artifact predicate.
- Adapter test reading invalid/valid review file.
- Workflow-race test still passes after adding valid markers to test fixture files.

# Plan 5 — Subagent workflow contract cleanup

Focus: make workflow and subagents cooperate through explicit artifacts, not hidden context.

## Goal

Define a narrow contract for workflow-subagent calls:

- every workflow-spawned subagent gets explicit input file paths
- every workflow-spawned subagent writes explicit output path
- default context should be `fresh` for workflow subagents unless a phase explicitly needs fork
- no model override in workflow calls

## Non-goals

- Do not change user-created agents.
- Do not delete `.pi-subagents` yet.
- Do not force all subagent calls globally to fresh.

### Identification

- `src/extensions/workflow/modes/quick.ts`

### Change

In workflow `tool_call` handler, when tool is `subagent` and workflow is active:

- If `context` is absent, set `context: "fresh"`.
- If `model` is present, remove or block it for workflow-owned phases.
- Force absolute `output` for artifact-owning phases as currently done.

  - `Workflow phase plan expects one subagent owner for plan.md; use single {agent, task}`

Leave `loop` to Plan 3 engine-owned orchestration.

### Verification

- Workflow ignores/bans model override.
- Single output goes to correct workflow artifact path.

Failure cases:

- Parallel/chain call in single-owner artifact phase is blocked clearly.
- Absolute output explicitly provided by workflow engine still respected.

Regression checks:

- Non-workflow subagent calls unchanged.
- Management calls (`action: "list"`, `get`, `doctor`) do not create phase artifacts.

Tests:

- Adapter `tool_call` mutates `{agent:"architect"}` to include output + fresh context.
