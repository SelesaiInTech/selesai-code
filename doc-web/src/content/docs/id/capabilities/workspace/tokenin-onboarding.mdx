Extension `tokenin-onboarding` memandu user pertama kali menambahkan akun Token-In agar Selesai dapat mengautentikasi dengan provider model. Extension juga menyediakan command `/tokenin` untuk mengelola beberapa akun setelah onboarding.

## Penyiapan dan prasyarat

- Extension ini dibundel bersama Selesai. Dimuat otomatis; tidak perlu diinstal terpisah.
- Hanya berjalan saat startup interaktif pertama (`event.reason === "startup"`) sampai marker onboarding ditulis.
- Memerlukan sesi TUI interaktif.
- Anda membutuhkan token Token-In dari `https://token-in.selesai.in/dashboard/tokens`.

## Yang disiapkan

- Menulis `~/.selesai/agent/.tokenInOnboardingComplete` setelah onboarding selesai atau dilewati.
- Menyimpan kredensial aktif di `auth.json` Selesai via `AuthStorage`.
- Menyimpan detail multi-akun di `~/.selesai/agent/tokenin-auth.json` dengan file mode `0o600`.
- Akun pertama yang ditambahkan selama onboarding diatur sebagai aktif secara otomatis.

## Yang dapat dilakukan

- Saat pertama kali berjalan, konfirmasi ingin menghubungkan Token-In, buka dashboard, tempel token, dan aktifkan akun.
- Menambahkan akun lain nanti dengan `/tokenin add`.
- Mengalihkan akun aktif dengan `/tokenin switch`.
- Menghapus akun yang tersimpan dengan `/tokenin remove` (tidak dapat menghapus akun aktif; alihkan dulu).
- Memeriksa kuota Token-In dengan `/tokenin usage`: mengkueri endpoint LiteLLM `/key/info` dengan token aktif dan menampilkan pengeluaran, anggaran, sisa, dan waktu reset dalam kotak.
- Menyimpan beberapa token dan mengandalkan failover otomatis. Jika kunci aktif gagal dengan error 401, 429, atau anggaran/kuota, ekstensi beralih ke akun tersimpan lain dan menempatkan kunci yang gagal dalam cooldown 5 menit sebelum mencoba lagi.

## Perintah, tool, dan shortcut

| Perintah | Deskripsi |
| --- | --- |
| `/tokenin add` | Buka dashboard Token-In, tempel token, dan tambahkan ke `tokenin-auth.json`. Jika ini akun pertama, ia menjadi aktif. |
| `/tokenin switch` | Pilih akun tersimpan dan jadikan kredensial aktif. |
| `/tokenin remove` | Pilih akun tersimpan yang tidak aktif dan hapus. |
| `/tokenin usage` | Tampilkan kuota Token-In: pengeluaran, anggaran, sisa, dan waktu reset dari endpoint LiteLLM `/key/info`. |

Command memvalidasi bahwa token yang ditempel diawali `sk-`. Token tidak valid ditolak dan prompt mencoba lagi pada peluncuran berikutnya.

## Batasan dan keamanan

- Token disimpan di `~/.selesai/agent/tokenin-auth.json` dengan mode `0o600`. Key aktif juga ditulis ke `auth.json` Selesai.
- Jangan commit `tokenin-auth.json`, `auth.json`, atau file apa pun yang berisi token.
- Prompt onboarding tidak muncul lagi setelah file marker ada, meskipun percobaan pertama gagal. Gunakan `/tokenin add` untuk mencoba lagi atau menambahkan token lain.
- Setelah failover, kredensial aktif baru ditulis ke `tokenin-auth.json` dan `auth.json`, sehingga rotasi bertahan di sesi berikutnya.
- Perintah `/tokenin-onboard` **tidak** ada; gunakan `/tokenin add` atau tunggu onboarding pertama kali.
