Extension `workflow` menyediakan empat bentuk mode workflow sebagai **saved chain pi-subagents**. Empat perintah dibundel: `/workflow-prototype`, `/workflow-quicktype`, `/workflow-task`, dan `/workflow-loop`. Setiap perintah meluncurkan chain-nya melalui pi-subagents — fase adalah langkah chain, gate manusia adalah langkah `checkpoint`, acceptance terverifikasi adalah gate `acceptance` chain, state tahan lama berada di mission yang dibuat otomatis, dan resumability berasal dari retained children pi-subagents.

## Penyiapan dan prasyarat

- Extension ini dibundel bersama Selesai. Dimuat otomatis; tidak perlu diinstal terpisah.
- Chain diluncurkan melalui extension `pi-subagents`, yang juga dibundel dan harus dimuat.
- Memerlukan sesi TUI interaktif.
- Roster agent Selesai (`architect`, `builder`, `commentator`, `explorer`, `recapper`, `researcher`) menyediakan langkah-langkah chain.

## Yang disiapkan

- Mendaftarkan satu slash command per mode: `/workflow-prototype`, `/workflow-quicktype`, `/workflow-task`, `/workflow-loop`.
- Setiap command meluncurkan chain pi-subagents (`launchSlashSubagent`) dengan goal sebagai `{task}` chain.

### Chain mode

| Mode | Langkah chain |
| --- | --- |
| `task` | architect (plan) → checkpoint → explorer (reuse) → recapper (handoff) → checkpoint → builder (implementasi, acceptance terverifikasi) → commentator (review) → checkpoint |
| `prototype` | researcher (research) → architect (plan) → checkpoint → explorer (reuse) → recapper (handoff) → checkpoint → builder (implementasi, acceptance terverifikasi) → commentator (review) → checkpoint → commentator (audit diff yang belum di-commit) |
| `quicktype` | sama dengan `prototype` tanpa langkah researcher |
| `loop` | builder (implementasi, acceptance terverifikasi) → commentator (review) → checkpoint — putaran build↔review langsung untuk rencana yang sudah disepakati |

- Gate manusia adalah langkah `checkpoint`: setujui dengan `subagent({ action: "approve-checkpoint", id })`, tolak dengan `reject-checkpoint`. Checkpoint yang ditolak menghentikan chain.
- Langkah builder membawa gate `acceptance` chain (level `checked` dengan bukti `commands-run` dan `changed-files`).
- State proses tahan lama berada di **mission** yang dibuat otomatis per peluncuran (state, artifact, keputusan, receipt); periksa dengan `mission.list` / `mission.show`.
- Resumability adalah retained children pi-subagents: `children.list` plus `runs.run({ resume })` untuk melanjutkan run.

## Perintah, tool, dan shortcut

| Perintah | Deskripsi |
| --- | --- |
| `/workflow-prototype <goal>` | Jalankan chain prototype penuh (research → plan → reuse → handoff → loop → audit). |
| `/workflow-quicktype <goal>` | Jalankan chain prototype lebih cepat tanpa research. |
| `/workflow-task <goal>` | Jalankan chain task (plan → reuse → handoff → build↔review). |
| `/workflow-loop <goal>` | Jalankan putaran builder/reviewer langsung untuk rencana yang sudah disepakati. |

## Batasan dan keamanan

- Chain diluncurkan secara asinkron; kartu hasil langsung, snapshot, dan notifikasi berasal dari UX slash pi-subagents.
- Setiap command membutuhkan goal yang tidak kosong; pemanggilan kosong menampilkan usage alih-alih meluncurkan.
- Engine tahan lama sebelumnya (state machine, run state `workflow.json`, tool `write_workflow_artifact` / `end_workflow`, dan artifact fase yang divalidasi marker) sudah dihapus. Empat mode adalah chain; marker fase dan penulisan artifact milik parent bukan bagian dari desain ini.
- Putaran build↔review didorong oleh segmen `builder → commentator → checkpoint`: review blocking menolak checkpoint, dan Anda menjalankan ulang `/workflow-<mode>` (atau resume/append) untuk putaran berikutnya. Tidak ada cap iterasi otomatis.

## Migrasi

Run aktif dari engine lama (`.selesai/artifacts/*/workflow.json`) **tidak dapat dilanjutkan**. File run lama dapat dihapus; mulai baru dengan `/workflow-<mode> <goal>`.
