`workflow` adalah skill bawaan yang membantu agen parent mengorkestrasi implementasi dengan `pi-subagents`. Skill ini menggantikan extension `/workflow-*` lama beserta pipeline auto-loop tetapnya.

Gunakan secara inline dengan `$workflow`, atau minta Selesai mengorkestrasi implementasi. Ini adalah lapisan kebijakan, bukan runtime atau sistem slash-command terpisah.

## Penyiapan dan prasyarat

`workflow` dan `pi-subagents` dibundel. Tidak diperlukan instalasi terpisah.

## Yang disiapkan

Skill ini menyediakan panduan orkestrasi khusus parent; skill ini tidak mendaftarkan runtime workflow atau slash command.

## Yang dapat dikonfigurasi

Skill ini tidak memiliki pengaturan persisten. Sesuaikan alur yang diminta dengan tugas, lalu gunakan kontrol `pi-subagents` normal untuk run yang didelegasikan.

## Yang dapat dilakukan

Panggil `$workflow` secara inline, atau minta Selesai mengorkestrasi implementasi.

## Perintah, tool, dan shortcut

Gunakan `$workflow`; peluncuran terkoordinasi memakai tool `subagent` yang sudah ada.

## Batasan dan keamanan

Parent tetap bertanggung jawab atas cakupan, penerimaan, dan keputusan kapan berhenti. Pertahankan satu writer per checkout.

## Cara kerja

Skill ini bersifat delegation-first: saat aktif, parent menguraikan permintaan menjadi subtask yang sempit dan mendelegasikannya ke subagent, bukan mengimplementasikan langsung. Parent memiliki klasifikasi, cakupan, keputusan, sintesis, dan penerimaan akhir.

Pemetaan subtask→agen yang umum:

| Subtask | Agen |
| --- | --- |
| Rekonesans codebase / mencari seam | `scout` atau `explorer` |
| Riset eksternal/tidak pasti | `researcher` |
| Perencanaan implementasi | `architect` |
| Implementasi terbatas | `worker` atau `builder` |
| Review independen | `reviewer` atau `commentator` |
| Perbaikan hasil sintesis parent | `worker` |

Pertahankan satu writer per checkout; hanya discovery, research, review, dan validasi read-only yang independen yang berjalan paralel. Untuk keputusan arsitektur atau produk yang material, selesaikan terlebih dahulu dengan `oracle` atau Council Mode sebelum implementasi.

## Menggunakan tahap delegasi

Skill ini memakai API `workflowScript` dari `pi-subagents` untuk koordinasi: `runs.run` untuk tahap berurutan, `runs.all` untuk fanout independen, dan JavaScript biasa untuk percabangan dan agregasi. Peran bawaan dapat menyimpan artefak ringkas seperti `context.md`, `research.md`, `plan.md`, laporan implementasi, dan review; teruskan hanya artefak yang dibutuhkan peran berikutnya melalui `reads`. Reviewer harus memeriksa diff aktual saat ini.

Handoff bersifat opsional. Gunakan untuk kelanjutan lintas-sesi, batas milestone, atau catatan permanen yang ditujukan untuk user—bukan sebagai tahap pipeline wajib.

## Review dan perbaikan

Untuk pekerjaan yang perlu review independen, tetapkan pemeriksaan penerimaan terfokus sebelum writer mulai. Jalankan hanya sudut review yang material untuk perubahan, sintesiskan temuan yang diterima di parent, lalu berikan satu tugas fix terarah kepada writer. Review ulang hanya setelah fix yang material. Berhenti saat validasi terfokus cukup, tidak ada blocker yang dapat ditindaklanjuti, atau keputusan user diperlukan.

## Migrasi dari `/workflow-*`

Command lama `/workflow-prototype`, `/workflow-quicktype`, `/workflow-task`, dan `/workflow-loop` telah dihapus. Mulai tugas baru dengan `$workflow`. Mission dan receipt pi-subagents yang sudah ada tetap tersedia sebagai bukti pekerjaan terdelegasi, tetapi tidak menjadikan pipeline tetap sebagai sumber kebenaran.
