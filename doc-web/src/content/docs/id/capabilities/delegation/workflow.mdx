## Apa ini dan mengapa membantu

Mesin workflow Selesai menjalankan alur kerja proyek multi-fase dalam mode `prototype`, `quick`, atau `task`. Workflow mempertahankan state dan artifact fase di disk, sehingga dapat dilanjutkan secara eksplisit setelah interupsi atau sesi terminal baru.

## Ketersediaan

Tersedia dalam `@selesai/code` sebagai extension `workflow` yang dibundel. User memulai atau melanjutkan workflow langsung dengan perintah slash.

## Mulai cepat

```sh
# Mulai workflow prototype (discovery-first)
/workflow-prototype

# Mulai workflow quick (lebih ringan)
/workflow-quick

# Mulai workflow task (implementasi langsung)
/workflow-task
```

## Mode

| Mode | Alur | Cocok untuk |
| --- | --- | --- |
| `prototype` | grill → research → plan → reuse → handoff → build/review loop → audit | Prototipe baru yang memerlukan discovery dan riset eksternal |
| `quick` | grill → plan → reuse → handoff → build/review loop → audit | Prototipe kecil dengan lebih sedikit ceremony |
| `task` | plan → reuse → handoff → build/review loop | Pekerjaan implementasi langsung |

## Konfigurasi

Workflow dikonfigurasi oleh file mode di `src/extensions/workflow/modes/`. Anda juga dapat membuat custom workflow mode sebagai skill.

```sh
# Lanjutkan workflow
selesai "/workflow-resume"      # contoh; perintah tepat mengikuti binding runtime Selesai
```

## Batasan dan edge case

- Agent tidak dapat memulai workflow secara otomatis; Anda harus menggunakan perintah slash.
- Langkah close eksplisit diperlukan untuk menyelesaikan workflow.
- Melanjutkan bergantung pada state yang persisten; jika file state dihapus, workflow dimulai ulang.
