Extension `workflow` menyediakan workflow proyek yang tahan lama dan dapat dilanjutkan kembali. Tiga mode dibundel: `prototype`, `quick`, dan `task`. Setiap mode memandu implementasi dari requirements hingga review, dengan artifact fase yang disimpan di disk sehingga Anda dapat menjeda dan melanjutkan pekerjaan.

## Penyiapan dan prasyarat

- Extension ini dibundel bersama Selesai. Dimuat otomatis; tidak perlu diinstal terpisah.
- Memerlukan sesi TUI interaktif.
- Setiap mode workflow menulis artifact fase di bawah direktori `.selesai/artifacts/` yang dihasilkan di dalam project. Pastikan path project dapat ditulis.
- Dukungan subagent digunakan secara internal (misalnya builder, commentator, architect, explorer, recapper); tool `subagent` harus tersedia.

## Yang disiapkan

- Mendaftarkan satu slash command per mode: `/workflow-prototype`, `/workflow-quick`, `/workflow-task`.
- Mendaftarkan tool `write_workflow_artifact` bersama dan tool `end_workflow`.
- Memelihara file run `workflow.json` di dalam direktori artifact setiap run sehingga run dapat dilanjutkan nanti.
- Menggunakan registry in-process global sehingga tiga mode tidak bertabrakan ketika dimuat bersama.

## Yang dapat dikonfigurasi

- Tidak ada file konfigurasi user khusus untuk workflow engine.
- Prompt dan validator fase fixed per mode di file source mode.
- Konfigurasi tidak langsung melalui pengaturan `subagents` memengaruhi perilaku child agent di dalam workflow.

## Yang dapat dilakukan

- Memulai siklus plan/implement/review yang tahan lama:

- Melanjutkan run sebelumnya: `/workflow-task resume` menampilkan daftar run yang dapat dilanjutkan, atau `/workflow-task resume <run-id>` melanjutkan run tertentu.
- Melanjutkan run aktif: `/workflow-task` (tanpa argumen) memungkinkan Anda melanjutkan di fase saat ini.
- Mengakhiri run yang terminal-ready dengan memanggil `end_workflow({ mode: "task" })` (atau `prototype` / `quick`).

### Fase mode

| Mode | Fase |
| --- | --- |
| `task` | plan → reuse → handoff → loop |
| `quick` | grilling → plan → reuse → handoff → loop → audit |
| `prototype` | grilling → research → plan → reuse → handoff → loop → audit |

- `grilling` mengajukan pertanyaan klarifikasi sampai frontier keputusan kosong.
- `research` mengumpulkan bukti eksternal bila diperlukan.
- `plan` menghasilkan rencana build yang harus diakhiri dengan `WORKFLOW_PLAN_STATUS: ready`.
- `reuse` mengeksplorasi codebase yang ada (dilewati otomatis jika tidak ada riwayat git).
- `handoff` menyusun dokumen konteks mandiri yang harus diakhiri dengan `WORKFLOW_HANDOFF_STATUS: ready`.
- `loop` menjalankan siklus review builder/commentator sampai commentator diakhiri dengan `WORKFLOW_REVIEW_STATUS: clean` atau cap iterasi maksimum tercapai.
- `audit` (hanya quick/prototype) melakukan review akhir terhadap perubahan yang belum di-commit.

## Perintah, tool, dan shortcut

| Perintah / tool | Deskripsi |
| --- | --- |
| `/workflow-prototype [<goal>\|resume]` | Jalankan workflow prototype penuh. |
| `/workflow-quick [<goal>\|resume]` | Jalankan workflow quick tanpa fase research. |
| `/workflow-task [<goal>\|resume]` | Jalankan workflow task dengan plan/reuse/handoff/loop. |
| `write_workflow_artifact({ content })` | Tulis artifact fase saat ini; engine maju ke fase berikutnya jika validator lolos. |
| `end_workflow({ mode: "task"\|"quick"\|"prototype" })` | Tutup secara eksplisit workflow yang terminal-ready. |

## Batasan dan keamanan

- Hanya satu run workflow yang aktif per mode pada satu waktu. Akhiri atau lepaskan run saat ini sebelum memulai yang lain.
- Artifact fase milik parent harus ditulis dengan `write_workflow_artifact`; tool call `write` atau `edit` langsung diblokir saat workflow aktif.
- `loop-complete.md` milik engine ditulis otomatis ketika review bersih terdeteksi. Jangan menulisnya sendiri.
- Putaran review loop dibatasi (default 3). Review blocking pada batas mem-pause loop dengan peringatan.
- Run workflow yang selesai tetap dapat dilanjutkan sampai `end_workflow` menulis `status: completed` ke file run.
- Run tidak pernah auto-resume setelah reload. Anda harus secara eksplisit memanggil `resume`.
