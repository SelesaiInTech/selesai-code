Extension `workflow` menyediakan empat bentuk mode workflow sebagai **workflow auto-loop scripted pi-subagents**. Empat perintah dibundel: `/workflow-prototype`, `/workflow-quicktype`, `/workflow-task`, dan `/workflow-loop`. Setiap perintah meluncurkan `workflowScript` melalui pi-subagents — fase mode berjalan sebagai langkah `runs.run`, dan putaran build↔review berulang otomatis hingga commentator melaporkan bersih. `workflowScript` tidak memiliki checkpoint, jadi tidak ada gate manusia. State tahan lama berada di mission yang dibuat otomatis per peluncuran.

## Penyiapan dan prasyarat

- Extension ini dibundel bersama Selesai. Dimuat otomatis; tidak perlu diinstal terpisah.
- Workflow scripted diluncurkan melalui extension `pi-subagents`, yang juga dibundel dan harus dimuat.
- Memerlukan sesi TUI interaktif.
- Roster agent Selesai (`architect`, `builder`, `commentator`, `explorer`, `recapper`, `researcher`) menyediakan fase-fase workflow.

## Yang disiapkan

- Mendaftarkan satu slash command per mode: `/workflow-prototype`, `/workflow-quicktype`, `/workflow-task`, `/workflow-loop`.
- Setiap command meluncurkan workflow scripted pi-subagents (`launchSlashSubagent`) dengan goal disuntikkan ke `workflowScript` mode tersebut.

### Skrip mode

| Mode | Fase scripted |
| --- | --- |
| `task` | architect (plan) → explorer (reuse) → recapper (handoff) → auto loop build→review→fix (builder → commentator → builder fix, hingga bersih) |
| `prototype` | researcher (research) → architect (plan) → explorer (reuse) → recapper (handoff) → auto loop build→review→fix (builder → commentator → builder fix, hingga bersih) → commentator (audit diff yang belum di-commit) |
| `quicktype` | sama dengan `prototype` tanpa langkah researcher |
| `loop` | auto loop build→review→fix (builder → commentator → builder fix, hingga bersih) — putaran langsung untuk rencana yang sudah disepakati |

- Fase setiap mode berjalan sebagai langkah `runs.run` di dalam `workflowScript`. Tidak ada checkpoint: skrip bersifat one-shot-and-sleep, dan review independen commentator adalah gate dari loop.
- Setiap peluncuran meng-emit goal-nya di awal (terlihat di `subagent status` → workflow emits dan kartu live) dan menamai mission sesuai goal (`mission.list` / `mission.show`).
- Putaran build→review→fix berulang otomatis hingga output reviewer cocok dengan marker `WORKFLOW_REVIEW_STATUS: clean`; kunci `runs.run` unik per putaran (`build-1`, `review-1`, `fix-1`, `build-2`, …). Review yang blocking memicu putaran fix yang hanya mengerjakan temuan reviewer; build berikutnya melanjutkan dari catatan sisa pekerjaan review.
- State proses tahan lama berada di **mission** yang dibuat otomatis per peluncuran (state, artifact, keputusan, receipt); periksa dengan `mission.list` / `mission.show`.
- Saat budget fan-out per-run (`maxSubagentSpawnsPerRun`) habis di tengah loop, workflow async me-relaunch otomatis sebagai run top-level baru dengan budget baru dan terus berputar hingga commentator melaporkan bersih atau cap auto-relaunch (`maxWorkflowAutoRelaunches`, default 12; 0 = tak terbatas) tercapai. Plan dan progress file membawa semua state antar relaunch.
- Workflow diluncurkan secara asinkron; pulihkan atau lanjutkan melalui `mission.list` dan `status` run async.

## Perintah, tool, dan shortcut

| Perintah | Deskripsi |
| --- | --- |
| `/workflow-prototype <goal>` | Jalankan workflow scripted prototype penuh (research → plan → reuse → handoff → auto loop → audit). |
| `/workflow-quicktype <goal>` | Jalankan workflow scripted prototype lebih cepat tanpa research. |
| `/workflow-task <goal>` | Jalankan workflow scripted task (plan → reuse → handoff → auto loop). |
| `/workflow-loop <goal>` | Jalankan auto loop build→review→fix langsung untuk rencana yang sudah disepakati. |

## Batasan dan keamanan

- Workflow diluncurkan secara asinkron (`async: true`); kartu hasil langsung, snapshot, dan notifikasi berasal dari UX slash pi-subagents.
- Setiap command membutuhkan goal yang tidak kosong; pemanggilan kosong menampilkan usage alih-alih meluncurkan.
- Engine tahan lama sebelumnya (state machine, run state `workflow.json`, tool `write_workflow_artifact` / `end_workflow`, dan artifact fase yang divalidasi marker) sudah dihapus. Empat mode adalah workflow auto-loop scripted: putaran build→review→fix berulang hingga commentator melaporkan bersih, dan tidak ada gate manusia.
- Catatan resume `workflow.json` lama tetap sebagai catatan migrasi: run aktif dari engine lama tidak dapat dilanjutkan.

## Migrasi

Run aktif dari engine lama (`.selesai/artifacts/*/workflow.json`) **tidak dapat dilanjutkan**. File run lama dapat dihapus; mulai baru dengan `/workflow-<mode> <goal>`.
