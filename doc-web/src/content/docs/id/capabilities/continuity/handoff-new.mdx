Extension `handoff-new` membuat prompt kelanjutan segar dari percakapan saat ini dan memulainya dalam sesi baru yang bersih. Ini mereset konteks dan mengurangi pengeluaran token ketika percakapan telah membesar atau berubah arah. Klien RPC dapat memakai command `handoff_new` untuk alur yang sama di host tanpa antarmuka (headless).

## Penyiapan dan prasyarat

- Extension ini dibundel bersama Selesai. Dimuat otomatis; tidak perlu diinstal terpisah.
- Berfungsi di TUI terminal serta host non-TUI/RPC seperti VS Code. Pada host non-TUI, pembuatan berjalan langsung tanpa loader terminal.
- Memerlukan model yang dipilih dan kredensial API yang valid agar dokumen handoff dapat dibuat.
- Model digunakan untuk meringkas percakapan; hasilnya dikirim sebagai prompt pertama dari sesi baru.

## Yang disiapkan

- Mendaftarkan slash command `/handoff-new`.
- Membaca branch sesi saat ini, termasuk entri pesan dan kompaksi.
- Memanggil model yang dikonfigurasi dengan system prompt yang meminta dokumen handoff dan mempertahankan struktur branch di sekitar ringkasan kompaksi.
- Memulai sesi baru yang parent-nya adalah file sesi saat ini, diisi dengan teks handoff yang dibuat.
- Memancarkan entri kustom `handoff-new` di sesi saat ini sebagai jejak.

## Yang dapat dilakukan

- Jalankan `/handoff-new` untuk melanjutkan dari sesi bersih setelah model meringkas thread saat ini.
- Jalankan `/handoff-new implement the remaining database migrations` untuk memberitahu sesi berikutnya fokus yang tepat.
- Gunakan output sebagai prompt kelanjutan yang dapat diedit sebelum sesi baru dimulai.

## Perintah, tool, dan shortcut

| Perintah | Deskripsi |
| --- | --- |
| `/handoff-new [goal]` | Menghasilkan dokumen handoff dan memulai sesi baru bersih darinya. |
| RPC `handoff_new` | Menghasilkan handoff dan memulai sesi anak bersih; menerima `goal` opsional. |
| `$selesai-handoff [goal]` | Meminta agent yang didukung skill meluncurkan sesi Selesai background dengan ringkasan handoff alih-alih mengedit di tempat. |

## Batasan dan keamanan

- Prompt model secara eksplisit meminta redaksi informasi sensitif seperti API key, password, atau PII, tetapi Anda tetap harus memeriksa handoff yang dibuat sebelum dikirim.
- Pembuatan handoff memerlukan model dan API key yang berfungsi. Jika pembuatan gagal, tidak ada sesi baru yang dibuat.
- Sesi asli tetap utuh dan masih dapat dilanjutkan atau dinavigasi via `/tree`.
- Skill `selesai-handoff` adalah resource pendamping; bukan entrypoint extension bundled yang terpisah.
