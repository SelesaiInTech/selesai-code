## 0.13.13 — Zentui Thinking (Eksperimental), pi-subagents 0.64.0, reorganisasi skill desain

- **Zentui Thinking (Eksperimental).** Ekstensi pi-zentui bawaan menambahkan renderer thinking privat opsional dengan tiga mode — `rail` (setiap label ter-parse dalam setiap run thinking kontigu native), `tree` (lima label terbaru per run), dan `streaming` (baris akhir yang dirender host dengan folding dan timing). Nonaktif secara default; konfigurasikan melalui `/zentui` atau `components.thinkingSteps` di `zentui.json`. Streaming aktif dapat beralih langsung ke Rail atau Tree, dan Rail serta Tree dapat saling beralih langsung; pengaktifan pertama, pengaktifan ulang setelah nonaktif langsung, dan masuk ke Streaming dari mode struktural memerlukan restart Pi. Fail-open: kegagalan startup, konstruktor hilang, tata letak child privat yang tidak kompatibel, batas parser, error tema/render/lebar, dan kepemilikan patch yang tergeser semuanya kembali ke thinking native penuh. Diuji terhadap Pi 0.80.5, 0.82.1, 0.83.0, 0.84.0, dan 0.84.4.
- **pi-subagents diporting ke upstream v0.64.0.** Aturan peluncuran watchdog (`subagents.watchdog.rules`) dengan glob izin/tolak model per-role, tool `watchdog_diff` read-only, irama review child yang dapat dikonfigurasi, instruksi reviewer `WATCHDOG.md`, peringatan watchdog yang ditampilkan di hasil parent dan bukti acceptance, serta status workflow/async yang lebih tenang. Pengaturan watchdog yang tidak didukung dan tidak pernah berlaku kini ditolak, dan auto-follow watchdog dihapus. Hardening perbaikan-tulis async-status khas fork tetap dipertahankan.
- **Reorganisasi skill desain bawaan.** Skill desain kini dikirim sebagai satu salinan kanonik per skill: `brutalist`, `minimalist`, `output`, `redesign`, `soft`, `stitch`, `taste`, dan `taste-v1` menggantikan varian duplikat `*-ui` / `*-skill` / `*-v1` sebelumnya, dan field frontmatter `category`/`license` dihapus dari skill yang tersisa.

## 0.13.12 — Lanjut otomatis setelah batas token output

- **Respons yang terpotong oleh batas token output kini dilanjutkan otomatis.** Saat model berhenti karena mencapai batas maksimum token output (`stopReason: "length"`) di tengah respons, Selesai mengantrekan pesan lanjutan "lanjutkan dari bagian terakhir" dan meminta ulang model alih-alih berhenti dengan error "response may be incomplete". Tool call yang terpotong sudah ditangani ulang oleh agent loop; ini mencakup teks yang terpotong. Lanjutan dibatasi maksimal 3 kali berurutan (penghitung direset pada setiap berhenti normal) sehingga model yang terus mencapai batas tidak berputar selamanya, dan length stop yang disebabkan tekanan konteks tetap memicu compaction terlebih dahulu.

## 0.13.11 — Perintah RPC get_skills, paritas loader working, ekstensi herdr-agent-state

- **Perintah RPC `get_skills`.** Perintah RPC baru yang mengembalikan katalog skill ter-resolve (satu entri per skill yang ditemukan dengan status enable efektifnya) plus pola `settings.skills` gabungan `global + project` mentah, sehingga host dapat mencerminkan permukaan toggle `/skills` TUI tanpa mengimplementasikan ulang semantik `isEnabledByOverrides`. Tersedia pada klien bertipe sebagai `RpcClient.getSkills()`.
- **Paritas loader `working` RPC.** `ctx.ui.setWorkingMessage()`, `setWorkingVisible()`, dan `setWorkingIndicator()` kini memancarkan `extension_ui_request {method: "working"}` fire-and-forget (field patch message/visible/frames/intervalMs) alih-alih no-op dalam mode RPC, sehingga host dapat merender baris loader streaming.
- **Ekstensi herdr-agent-state.** Ekstensi bundled baru yang melaporkan status siklus hidup sesi (`working`/`blocked`/`idle`) plus referensi sesi ke pane Herdr melalui `HERDR_SOCKET_PATH`. State instance berada di dalam factory sehingga sesi penerus setelah `/new`, fork, resume, atau reload tetap melapor; hanya `reportSeq` monoton yang tetap di level modul untuk memenuhi guard urutan per-source Herdr.

### Diperbaiki
- **handoff-new tidak lagi gagal membuat sesi.** Callback `setup` membaca nama sesi dari ctx ekstensi yang sudah diganti, sehingga melempar error stale-ctx dan membatalkan `newSession` dengan "Failed to create session". Nama kini ditangkap sebelum `newSession()` dan diteruskan ke `setup` sebagai nilai biasa; nama sesi tetap diwariskan seperti sebelumnya.

## 0.13.10 — Perintah RPC rev-3, nama sesi handoff-new, subagent builtin-only

- **Batch paritas RPC rev-3.** Perintah RPC baru untuk host headless: `navigate_tree` (navigasi leaf session-tree dengan opsi summarization/instruksi), `list_sessions` (penemuan sesi di cwd atau semua scope), `rename_session`, `delete_session` (trash-first, menolak sesi yang aktif), dan `set_session_models` (mutasi scoped-model ephemeral). Field opsi baru: `prompt.queueWhileCompacting` (buffer prompt selama compaction), `cycle_model.direction` (forward|backward), `get_available_models.refresh` (refresh katalog model on-demand), serta `export_html.themeName` / `share_gist.themeName` theme passthrough.
- **handoff-new membawa nama sesi.** Sesi baru yang dimulai oleh `/handoff-new` atau RPC `handoff_new` kini mewarisi nama sesi saat ini alih-alih dimulai tanpa nama.
- **pi-subagents hanya mengirim agen builtin.** Ekstensi pi-subagents kini hanya mengirim agen builtin (`advisor`, `delegate`, `oracle`, `researcher`, `reviewer`, `scout`, `worker`) dan menghapus definisi agen kustom serta adapter agen Claude Code / Codex / Cursor, sehingga run subagent kompatibel di host mana pun tanpa CLI eksternal.

## 0.13.3 — Rotasi kunci Token-In dan rekonsiliasi biaya live

- Menambahkan **auto-failover multi-kunci ke Token-In**: ekstensi `tokenin-onboarding` kini mendaftarkan provider `tokenin` yang `streamSimple`-nya otomatis beralih ke akun cadangan tersimpan saat kunci aktif terkena error 401, 429, atau anggaran/kuota. Pembungkus fetch kini menyelesaikan capture sebelum SDK provider men-finalisasi pesan, sehingga `message_end` menerapkan total hasil rekonsiliasi langsung alih-alih hanya mencatat entri sesi kustom; provider yang payload-nya tidak memuat biaya tetap mempertahankan estimasi rate card.

## 0.13.2 — Dukungan submodule Rewind, pembersihan Herdr status bridge

- Menambahkan **dukungan submodule ke `pi-rewind-hook`**: exact rewind kini memotret commit gitlink dan checkout commit submodule target, dengan pemeriksaan keamanan — path submodule harus tetap sama, worktree harus bersih dan terinisialisasi, dan commit target harus tersedia secara lokal. State submodule yang tidak didukung (kotor, belum diinisialisasi, path ditambah/dihapus, submodule bersarang) ditolak dengan error yang jelas alih-alih dilaporkan sebagai exact restore.
- Memperbaiki **race pada retention sweep**: ref store rewind kini diperbarui dengan compare-and-swap dan retry, sehingga sesi konkuren yang menambah snapshot di tengah sweep tetap dipertahankan; startup sweep digunakan kembali saat penggantian sesi alih-alih menjalankan sweep kedua.
- Mengubah **Herdr status bridge** di `pi-subagents` agar tidak lagi mengirim `--agent pi` / `--applies-to-source herdr:pi`; state label dilaporkan langsung di bawah source `pi-subagents:herdr`.
- Mengubah **kemasan `pi-rewind-hook`** agar mendeklarasikan `@selesai/code` sebagai peer dependency (sebelumnya devDependency) dan menaikkannya ke 1.8.6.

## 0.11.0 — Penamaan sesi otomatis, rekonsiliasi biaya, dan tool display bawaan
