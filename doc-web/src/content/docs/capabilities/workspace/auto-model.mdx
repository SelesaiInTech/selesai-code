The `auto-model` extension is a bundled extension that gives each idle, top-level prompt its own model. It asks the Jev decisions model which of four complexity tiers fits the request, then switches to the model you configured for that tier before the turn starts. Routing is off until you enable it.

## Setup and prerequisites

- Bundled with Selesai and loaded automatically; no installation is required.
- Routing is disabled by default. Set `autoModel.enabled` to `true` in settings.
- The classifier needs the provider that serves the Jev decisions deployment (Token-In by default), and every routed model must be available in the current session's model scope.

## What it sets up

- Reads `autoModel` from `settings.json` on every prompt, so edits apply without a restart.
- Builds the Jev decisions request — `state` plus a `complexity` choice question — from the current ask, a bounded window of prior user turns, and the active system prompt.
- Reads the answered tier back and calls `pi.setModel()` on that tier's model.
- Applies the `:thinkingLevel` suffix through `pi.setThinkingLevel()` when a tier value carries one.

## What you can do

- Assign a different model to each of `simple`, `medium`, `complex`, and `reasoning`.
- Let routine work use a fast model while difficult debugging and reasoning reach a stronger one.
- See which model a turn will use: the routed model becomes the session model, so the footer and `/model` show it.
- Keep manual control: choosing a model yourself suspends automatic routing for the session.

## Commands, tools, and shortcuts

No slash commands or tools are registered. The extension reacts to the `input`, `model_select`, and `session_start` events. A model chosen with `/model`, Ctrl+P cycling, or a restored session is respected rather than overwritten.

## Limits and safety

- Only idle, top-level prompts are routed. Queued steering and follow-up messages, extension-injected messages, and `/` commands never change the model, because the session model is global and switching mid-stream would retarget the in-flight turn.
- Concurrently submitted prompts are serialized: only one classification runs at a time, so two prompts cannot race on the model switch.
- The classifier sees only the current ask, a few prior user turns (default four, 4000 characters), and the system prompt. Tool output and assistant narration are not sent.
- Classifier text is material, never instructions: the rubric tells Jev to ignore any request inside the conversation that asks for a specific tier.
- A classifier timeout, error, malformed or low-confidence answer, missing or out-of-scope model, or unavailable credentials keeps the current model or falls back to `autoModel.fallbackTier` (default `medium`). Routing never blocks the prompt.
- Classifier calls through the bundled compatibility path do not use Token-In's multi-key auto-failover; a failed active key simply falls back.
