The model-prompt-injector is a bundled extension that injects a model-specific prompt into the system prompt whenever the active model matches a rule. Rules live in a config file next to the extension; nothing is exposed to user settings, and `/reload` re-reads the config.

## Setup and prerequisites

- Bundled with Selesai and loaded automatically.
- Config lives in `src/extensions/model-prompt-injector/config.json` in the host codebase; there is no user-level settings surface.
- `/reload` re-reads the config file after editing.

## What it sets up

- Reads an array of `rules`, each with a `match` glob list, a `mode` (`prepend`, `append`, or `replace`), a `prompt`, and an `enabled` flag.
- When the active model matches a rule, the prompt is injected into the system prompt at the configured position.
- Matchers support provider/model pairs, provider wildcards, any-model references, bare names, and `*`.

## What you can configure

Rules are edited in `config.json` next to the extension source; there are no user-facing settings, environment variables, or slash commands for this extension.

## What you can do

- Prepend, append, or replace system-prompt content per model family.
- Match specific models or entire provider families with glob patterns.
- Disable rules without deleting them.

## Commands, tools, and shortcuts

- `/reload` — re-read the extension config after editing `config.json`.

## Limits and safety

- Config changes require a reload to take effect.
- A `replace` rule overwrites the relevant prompt portion; use it deliberately.
- This extension only alters the system prompt for matching models; it does not change routing or model selection.
