# Subagent delegation

## What it is and why it helps

Selesai bundles the `pi-subagents` extension and adapts it to the Selesai runtime. It provides focused agent roles, lifecycle management, and run controls that let you delegate work without losing visibility or control.

## Availability

Included in `@selesai/code` starting at version `0.5.22` with roles such as:

- `architect`
- `builder`
- `commentator`
- `explorer`
- `recapper`
- `researcher`

## Quick start

Use natural-language prompts to delegate work:

```text
Ask the architect to challenge this plan before we implement it.
```

```text
Run parallel commentator agents for correctness, tests, and unnecessary complexity.
```

```text
Have the builder implement this plan, then review the result.
```

## Configuration

Subagents are configured via project-local and user-level agent definitions. Common controls include:

- model/tool/skill overrides;
- foreground, background, parallel, or chained runs;
- tool/turn budgets;
- output schemas and artifact paths;
- worktree isolation for parallel tasks.

```sh
# Example: list available subagent commands in Selesai
selesai -p "list subagent roles and tools"
```

## Limits and edge cases

- Delegated agents run within the same host environment; trust boundaries are the same as the main session.
- Background runs continue until completion unless interrupted; steer them through the Selesai status/intercom interface.
- Model/tool budgets are enforced by Selesai; check budget usage in the footer status.
