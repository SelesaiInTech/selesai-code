The `workflow` extension provides durable, resumable project workflows. Four modes are bundled: `prototype`, `quicktype`, `task`, and `loop`. The direct `loop` mode is for work already planned in the parent conversation; it runs only builder/reviewer rounds.

## Setup and prerequisites

- This extension is bundled with Selesai. It is loaded automatically; you do not need to install it separately.
- Requires an interactive TUI session.
- Each workflow mode writes phase artifacts under a generated `.selesai/artifacts/` directory inside the project. Ensure the project path is writable.
- Subagent support is used internally (e.g., builder, commentator, architect, explorer, recapper); the `subagent` tool must be available.

## What it sets up

- Registers one slash command per mode: `/workflow-prototype`, `/workflow-quicktype`, `/workflow-task`, `/workflow-loop`.
- Registers the shared `write_workflow_artifact` tool and the `end_workflow` tool.
- Maintains a `workflow.json` run file inside each run's artifact directory so the run can be resumed later.
- Reuses a global in-process registry so the four modes do not conflict when loaded together.

## What you can do

- Start a durable plan/implement/review cycle:

<div class="install-command">
  <pre><code>/workflow-task add a persistent todo store with sqlite</code></pre>
  <button type="button" class="copy-button" data-command="/workflow-task add a persistent todo store with sqlite" aria-label="Copy command to clipboard">Copy</button>
  <span class="copy-status" role="status" aria-live="polite"></span>
</div>

- Resume a previous run: `/workflow-task resume` lists resumable runs, or `/workflow-task resume <run-id>` resumes a specific one.
- Continue an active run: `/workflow-task` (no arguments) lets you continue at the current phase.
- End a terminal-ready run by calling `end_workflow({ mode: "task" })` (or `prototype` / `quicktype` / `loop`).

### Mode phases

| Mode | Phases |
| --- | --- |
| `task` | plan → reuse → handoff → loop |
| `quicktype` | grilling → plan → reuse → handoff → loop → audit |
| `prototype` | grilling → research → plan → reuse → handoff → loop → audit |
| `loop` | loop (direct build ↔ review) |

- `grilling` asks clarification questions until the frontier of decisions is empty.
- `research` gathers external evidence when needed.
- `plan` produces a build plan that must end with `WORKFLOW_PLAN_STATUS: ready`.
- `reuse` explores the existing codebase (skipped automatically if there is no git history).
- `handoff` compiles a self-contained context document that must end with `WORKFLOW_HANDOFF_STATUS: ready`.
- `loop` runs builder/commentator review cycles until the commentator ends with `WORKFLOW_REVIEW_STATUS: clean` or the max iteration cap is reached. In direct `loop` mode, parent must synthesize the agreed conversation plan, constraints, and acceptance criteria into each fresh subagent prompt; no plan or handoff artifact is created.
- `audit` (quicktype/prototype only) performs a final review of uncommitted changes.

## Commands, tools, and shortcuts

| Command / tool | Description |
| --- | --- |
| `/workflow-prototype [<goal>\|resume]` | Run the full prototype workflow. |
| `/workflow-quicktype [<goal>\|resume]` | Run the quicker prototype workflow without a research phase. |
| `/workflow-task [<goal>\|resume]` | Run the task workflow with plan/reuse/handoff/loop. |
| `/workflow-loop [<goal>\|resume]` | Run direct builder/reviewer rounds for an already-agreed plan. |
| `write_workflow_artifact({ content })` | Write the current phase artifact; the engine advances to the next phase if validators pass. |
| `end_workflow({ mode: "task"\|"quicktype"\|"prototype"\|"loop" })` | Explicitly close a terminal-ready workflow. |

## Limits and safety

- Only one workflow run can be active per mode at a time. End or detach the current run before starting another.
- Parent-owned phase artifacts must be written with `write_workflow_artifact`; direct `write` or `edit` tool calls are blocked while a workflow is active.
- The engine-owned `loop-complete.md` is written automatically when a clean review is detected. Do not write it yourself.
- Loop review rounds are capped (default 3). A blocking review at the cap pauses the loop with a warning.
- Completed workflow runs remain resumable until `end_workflow` writes `status: completed` to the run file.
- Runs are never auto-resumed after reload. You must explicitly call `resume`.
