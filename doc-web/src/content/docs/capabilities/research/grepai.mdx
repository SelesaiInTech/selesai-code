The bundled `grepai` integration provisions the official semantic code-search CLI and configures its project-local embedding settings to use Selesai's Token-In-compatible LiteLLM proxy.

## Setup and prerequisites

- grepai is provisioned from the official `yoanbernabeu/grepai` GitHub release into Selesai's managed binary directory when no verified system binary is available.
- A Token-In credential must be configured (`/tokenin add`).
- grepai stores its project configuration at `.grepai/config.yaml`; the integration creates it lazily when a config-dependent grepai command is first used, or immediately with `/setup-grepai`.
- The integration forces `store.backend: gob`, so the index remains file-based in `.grepai/` and requires no external database.
- When a configured project starts, Selesai launches `grepai watch --background`; grepai performs the initial scan and keeps the index updated as files change.
- Set `PI_OFFLINE=1` to prevent managed binary downloads.

## What it sets up

- Downloads and checksum-verifies the latest grepai release for the current platform.
- Uses grepai's OpenAI-compatible provider with model `nomic-code`.
- Sets the endpoint to `https://lite.andlet.me/v1`; grepai appends `/embeddings`, so requests go to `https://lite.andlet.me/v1/embeddings`.
- Selects grepai's file-based GOB store with `store.backend: gob`.
- Resolves the active Token-In API key from Selesai auth storage and writes it to `.grepai/config.yaml` with mode `0600`; the key is never logged or passed in argv.
- Preserves unrelated grepai project settings.
- Starts the background watcher after `/setup-grepai` and on later Selesai startups for configured projects.

The integration uses 768 dimensions for `nomic-code`, based on the expected Nomic code-embedding width. The default GOB store is file-based and does not require a database collection dimension; verify the proxy's model metadata before manually switching to Postgres or Qdrant.

## What you can do

- Run `/setup-grepai` to install grepai, configure the current project, and begin indexing it.
- Ask the agent to run `grepai search "authentication flow"`; the watcher is started automatically before the first search when needed.
- Use `grepai watch --status` or `grepai watch --stop` to inspect or stop the automatic watcher.
- Use `GREPAI_DISABLED=1` to disable automatic provisioning and setup.
- Use `SELESAI_SKIP_GREPAI_SETUP=1` to keep provisioning but skip automatic project configuration.

## Commands, tools, and shortcuts

| Command | Description |
| --- | --- |
| `/setup-grepai` | Install grepai and configure the current project from the active Token-In credential. |
| `grepai init` | Upstream initialization command; Selesai's setup uses it with the OpenAI provider and `nomic-code`. |
| `grepai watch` | Manually start the foreground or background indexing watcher; configured projects start it automatically. |
| `grepai watch --status` | Check the automatic watcher status. |
| `grepai watch --stop` | Stop the automatic watcher. |
| `grepai search <query>` | Search the indexed project semantically. |
| `grepai trace ...` | Trace symbols/call relationships when supported by the installed grepai version. |

## Limits and safety

- grepai configuration is project-local, not a Selesai model-provider registration; its own Go process sends embedding requests.
- The Token-In key is stored in `.grepai/config.yaml` because upstream grepai only supports a literal `embedder.api_key` or the process-level `OPENAI_API_KEY` fallback. Keep `.grepai/` ignored and review file permissions.
- The integration fails open: if installation or setup fails, the original Bash command is allowed to continue.
- The `nomic-code` alias and its dimensions belong to the LiteLLM proxy, not the grepai repository; a proxy-side model change may require updating the project config.
